CASE 01 / LLM / RAG · OBSERVABILITY

마이크로서비스 오류를 식별하고 해소 방안을 제안하다

Kubernetes 운영 정보와 서비스 간 통신 흐름을 분석하고, 기존 사례 검색을 통해 오류 식별과 해소 방안 생성을 지원했습니다.

배경담당한 일기술적 접근검증과 범위Resources

CONTEXT

어떤 문제를 다뤘나요?

컨테이너가 실행 중이어도 서비스 간 연결이나 기능 수행은 실패할 수 있습니다. 컨테이너 측면의 운영 정보와 마이크로서비스 측면의 통신 흐름을 함께 다루어 오류를 식별하고, 해소에 필요한 근거를 제공하는 연구입니다.

MY CONTRIBUTION

직접 담당한 일

01

오류를 관찰 가능한 정보로 구조화

kubectl apply의 배포 결과, describe의 리소스 이벤트, logs의 컨테이너 로그와 Jaeger의 통신 흐름을 수집·분석했습니다. 배포와 약결합 과정의 오류를 구분하고 총 10가지 오류 유형을 도출했습니다.

02

질문에 맞는 지식 베이스 설계

배포 오류는 기존 오류 내용을 임베딩하고 해소 방안은 메타데이터로 분리했습니다. 약결합 오류는 유스케이스와 정상 통신 흐름을 함께 저장해 같은 기능의 정상 동작과 비교하도록 구성했습니다.

03

검색과 답변 생성을 연결

Python·LangChain·ChromaDB로 RAG 파이프라인을 구현했습니다. 새 배포 오류와 유사한 사례를 검색해 해소 방안을 생성하고, 수집된 통신 흐름을 정상 흐름과 대조해 약결합 오류 유형을 식별했습니다.

APPROACH

오류와 해소 방안을 분리한 이유

유사 오류를 찾을 때 해소 절차의 문장이 검색 결과를 좌우하지 않도록, 오류 정보만 임베딩하고 해소 방안은 해당 사례의 메타데이터로 보관했습니다. 검색 목적에 맞게 데이터의 역할을 분리한 설계입니다.

VALIDATION & SCOPE

검증과 결과의 범위

오픈소스 마이크로서비스의 오류를 재현하고, Zero-Shot CoT·Self-Refine 등과 오류 식별 결과, 응답 시간, 토큰 사용량을 비교했습니다. 실험 구성과 분석은 석사학위논문 및 관련 공동 연구 논문으로 정리했습니다.

오류 식별과 해소 방안 생성까지를 다루는 연구 프로토타입입니다. 결과는 운영자가 검토할 오류 유형과 해소 방안으로 제공되며, 실제 운영 환경의 자동 복구 성과를 의미하지 않습니다.
